## Determinism and limits

`KeyboardTestHost` is a separate simulator-only app, excluded from install/archive products and absent from the shipping companion. It compiles the exact extension controller, keyplane, styling and routing files with `KEYBOARD_UI_TEST_HOST`. The controller is a child input surface under a real host text view; both editors suppress the system keyplane. Only the OS boundaries change: a document proxy backed by that text view, a private document identity following actual responder state, and a temporary vault URL. Production draft state, host-proxy validation, KeyboardKit key gestures, save and lexical retrieval execute normally. This avoids Settings automation, private preference formats and keyboard-daemon selection races observed in earlier simulator screenshots.

Each iPhone test supplies a new UUID-owned directory; termination/relaunch within the persistence journey retains that UUID. The Mac's Debug-only `--pill-ui-test <UUID>` flag selects its own temporary vault and defaults suite. Both use `notificationAccess: .disabled`, which disables private sync, key loading and notification access. UI jobs run serially inside their runner, use bounded observation waits and retain `.xcresult` bundles, failure screenshots and accessibility trees. No retry flag turns a failed assertion into a pass.

The Mac UI runner uses an ad-hoc signature without distribution entitlements. The unchanged `PillSelfTest` separately runs under App Sandbox and covers window flags, focus, shortcuts, dragging, visibility and animation timings. Neither test establishes physical-user delivery of a global shortcut.

Remaining manual checks: extension registration/Full Access and App Group sharing; real cross-process host-proxy behavior and a second host app; secure-field/app restrictions; key feel, long press/accents, caps-lock/repeat-delete/cursor-drag gestures and sound/haptics; physical extension memory/jetsam; signed-device key pairing and live two-device CloudKit/offline recovery. See [the device guide](../TESTING-TONIGHT.md).

## Reproduce

On macOS with Xcode 26.2, regenerate with `python3 native/Scripts/generate_project.py`, then use a current iPhone simulator UUID:

```sh
xcodebuild -project native/MindMachine.xcodeproj -scheme MindMachineKeyboardUITests \
  -destination 'platform=iOS Simulator,id=SIMULATOR_UUID' -parallel-testing-enabled NO \
  -resultBundlePath keyboard-ui.xcresult CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- CODE_SIGN_ENTITLEMENTS= test
xcodebuild -project native/MindMachine.xcodeproj -scheme MindMachinePillUITests \
  -destination 'platform=macOS,arch=arm64' -parallel-testing-enabled NO \
  -resultBundlePath pill-ui.xcresult CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  CODE_SIGN_ENTITLEMENTS= ENABLE_APP_SANDBOX=NO test
```
