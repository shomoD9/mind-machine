# Open-source components for capture, organization, and retrieval

Research checked 2026-09-29. This is a component survey for the [Scattered ambitious pitch](../map.md), not a stack decision. The product commitments are in [the MVP index](../mvp.md): preserve the maker's words and separate thoughts, permit adjacent unfinished dialogs and hotkey-created wikilinks, capture without classification, and show a note inside an app already open where one click takes it to the maker's chosen destination. The destination apps, cues, and exact capture interactions still need decisions.

## Answer

Reusable code exists for each part, but I found no verified open-source product that combines this capture surface with automatic organization and an in-app point-of-decision cue. The strongest pieces to inspect are **[Noty](https://github.com/aimen08/noty)** for native macOS global-shortcut capture, **[Noted](https://github.com/fabriziosalmi/noted)** for an Electron/Tiptap editor with wikilinks and quick capture, **[Web Remainder](https://github.com/farukak/web-remainder)** for browser-injected context cues, and **SQLite FTS5 plus [sqlite-vec](https://github.com/asg017/sqlite-vec)** for a small local retrieval index. The first three are MIT, MIT, and Apache-2.0 respectively; sqlite-vec is dual MIT/Apache-2.0. Their repositories are public and expose the relevant implementation, but none has been run or integrated in this research pass. [Noty repository and license](https://github.com/aimen08/noty), [Noted repository and license](https://github.com/fabriziosalmi/noted), [Web Remainder architecture and license](https://github.com/farukak/web-remainder), [SQLite FTS5](https://www.sqlite.org/fts5.html), [sqlite-vec repository](https://github.com/asg017/sqlite-vec).

The organizing decision should begin with **preserving source text plus optional derived metadata**. A fixed note schema does not require the maker to pick a category. Exact-source fields, explicit links, inferred links, and eventual decision destinations should be separate, so a cheap classifier can be wrong without corrupting the capture. This is a research recommendation, not a settled product decision. [Jev-Mem](https://github.com/libingzheren/Jev-Mem) demonstrates preserving observations and provenance while building inferred relations separately; [Karakeep](https://github.com/karakeep-app/karakeep) demonstrates both rules and model-assisted tags, although its bookmark workflow is not the maker's workflow.

## Organization: schema before agent

### Provisional capture record

The following is a **research proposal** for a minimum persisted record. It intentionally leaves unclear product choices open: whether a linked dialog is independent or subordinate; whether multi-thought text is automatically split while Explode is outside the MVP; and which apps or destinations matter. It can retain the data needed to answer those choices later.

```json
{
  "id": "stable-id",
  "created_at": "ISO-8601 timestamp",
  "updated_at": "ISO-8601 timestamp",
  "input_mode": "typed | spoken",
  "verbatim_text": "maker's original words or transcript",
  "display_text": "same text, with only accepted legibility edits",
  "source_ref": { "app": "optional", "url_or_document": "optional", "draft_ref": "optional" },
  "explicit_links": [
    { "selected_text": "phrase", "target_dialog_id": "stable-id", "source_span": [0, 6] }
  ],
  "status": "open | archived"
}
```

This record is a capture contract, not a demand for user input. A separate `derived_assessments` store can hold `{capture_id, kind, value, confidence, method, model_version, created_at, corrected_at}` for tentative labels and inferred connections. A separate `decision_events` store can later hold which cue appeared, which note was offered, destination, click/dismiss outcome, and timestamp. Keeping derived data separate makes it reversible and lets explicit wikilinks outrank uncertain inferred links. `source_span` needs a robust anchoring policy once editing behavior is specified; plain offsets alone will drift after text edits. [Web Remainder's anchor resolver](https://github.com/farukak/web-remainder) is an example of fallback anchoring after page changes. [Jev-Mem's observed/provenance and inferred-relationship separation](https://github.com/libingzheren/Jev-Mem) supports the general pattern, though its memory graph is for agent conversations.

### Cheap sorting ladder

| Method | Where it fits | Cost and failure mode |
| --- | --- | --- |
| Deterministic rules over source app, URL, explicit wikilinks, maker-confirmed destinations, and exact words | First pass; immediate, inspectable routing and constraints. [Karakeep](https://github.com/karakeep-app/karakeep) has a rule engine for tags/lists, showing this is practical at product scale. | No model fee; engineering cost is rule upkeep. Brittle for paraphrases and new themes. |
| Local full-text plus small embeddings | Candidate retrieval and provisional similarity links. [SQLite FTS5](https://www.sqlite.org/fts5.html) includes BM25 ranking; [sqlite-vec](https://github.com/asg017/sqlite-vec) stores and searches vectors in SQLite; [FastEmbed](https://github.com/qdrant/fastembed) runs ONNX text embeddings without a GPU. | No per-request provider fee, but model download, memory, CPU/battery, packaging, and update cost. Semantic neighbors can be related yet unusable at the current point of decision. sqlite-vec warns that it is pre-v1 and may break compatibility. |
| Typed decision model for a short, known option set | Score a small list of possible labels/destinations or decide whether to show a candidate. [Laya](https://github.com/NandhaKishorM/laya) supplies local open-weight choice/score/yes-no decisions and an evaluation harness; [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) supplies hosted typed decisions. | More judgment than rules, but still needs explicit candidate labels and measured thresholds. The model cannot invent a new destination from a fixed choice set. Laya's author reports degraded default accuracy for large option sets; shortlist first. [Laya limits](https://github.com/NandhaKishorM/laya). |
| Small generative model or hosted LLM | Only for genuinely open-ended extraction or hard ambiguous cases after cheaper stages fail. Karakeep combines similar-item embeddings and LLM tag suggestions. [Karakeep release notes](https://github.com/karakeep-app/karakeep/releases). | Prompt/inference latency and power or API spend; may produce tag sprawl, hallucinated specificity, and rewritten wording. Require validation and do not overwrite `verbatim_text`. |

**Jev specifically:** TypeSafe AI's Jev is a hosted System One model for typed `choice`, `score`, and yes/no decisions. The company currently advertises **$0.042 per million input tokens** and early access; pricing and access can change. Its [official JavaScript SDK](https://github.com/typesafe-ai/typesafe-sdk-js) is MIT and requires `TYPESAFE_API_KEY`. I found no first-party released Jev weights in the sources checked, so **the SDK being open source does not make Jev locally runnable**. [First-party announcement and pricing](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [SDK example](https://github.com/typesafe-ai/typesafe-sdk-js). [Laya](https://github.com/NandhaKishorM/laya) is a distinct Apache-2.0 local decision-model project with downloadable weights, not a Jev release. The MIT [Jev-Mem](https://github.com/libingzheren/Jev-Mem) library is an agent-memory architecture that uses Jev by default and added Laya as a local controller; its reported LoCoMo gains test answer quality in long-running agent conversations, **not** this product's sorting or point-of-decision success. It is worth studying for provenance, bounded candidate generation, tracing, and stopping, not adopting as the organization engine without a task-specific pilot. [Jev-Mem README and benchmark caveats](https://github.com/libingzheren/Jev-Mem).

[Karakeep](https://github.com/karakeep-app/karakeep) is the clearest working example of rule-based routing, automatic LLM tags, local-model support through Ollama, and semantic/hybrid search in one open codebase. Its 2026 release added similar-item tags as LLM hints to reduce tag proliferation. It is built for bookmarks, links, images, and lists; forcing captures into its bookmark ontology would impose classification that this maker should not perform at capture. Its AGPL-3.0 license also needs an explicit decision before incorporating code into a differently licensed product. [Karakeep README/license](https://github.com/karakeep-app/karakeep), [release notes](https://github.com/karakeep-app/karakeep/releases).

## Retrieval: a cue at the point of decision

[Web Remainder](https://github.com/farukak/web-remainder) is the closest verified code pattern for a note appearing *inside an existing web app*. Its Manifest V3 content script renders an isolated Shadow DOM overlay, matches URL scopes, follows single-page-app route changes, and restores notes using a multi-strategy anchor resolver. The repo is Apache-2.0 and small (21 commits shown when checked); treat it as an implementation reference requiring a pilot, not proven infrastructure. It restores pre-attached page notes. It does **not** choose which newly captured note would help the maker act, nor implement the product's one-click handoff. [Architecture, permissions, and license](https://github.com/farukak/web-remainder).

The code audit can start at [`src/content/anchor-resolver.ts`](https://github.com/farukak/web-remainder/blob/main/src/content/anchor-resolver.ts), [`annotation-manager.ts`](https://github.com/farukak/web-remainder/blob/main/src/content/annotation-manager.ts), and [`mutation-observer.ts`](https://github.com/farukak/web-remainder/blob/main/src/content/mutation-observer.ts); all three are listed in the [upstream source directory](https://github.com/farukak/web-remainder/tree/main/src/content).

A browser extension is technically capable of reading and changing page DOM through [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts); dynamic injection requires the [scripting permission plus host permission or temporary `activeTab`](https://developer.chrome.com/docs/extensions/reference/api/scripting). [WXT](https://github.com/wxt-dev/wxt) is an MIT extension framework with browser targets and file-based entrypoints. These sources support an in-page cue, but editable surfaces in Substack, X/Twitter, and chats need separate validation: editor DOM and site routes change; rich-text editors may hide document state in app-specific structures; host permissions and extension review affect installation. Those are engineering inferences from the content-script model, not verified integrations.

The retrieval pipeline worth testing is: detect an **allowed decision surface** (app/route plus, where permitted, the local draft context), fetch candidate captures through exact/source/link matches and FTS5, add vector neighbors if needed, score for **action fit and chosen destination**, then show at most a small number of notes with a one-click route. Keep a no-cue outcome when confidence is low. This pipeline is a proposal. It addresses the product's existing evidence that a note merely stored or generally resurfaced may fail to change the next act; see [When an intention comes back](09-when-an-intention-comes-back.md).

The repository's [interesting-resource.md](../../../interesting-resource.md) names `onepixelaway/interfaces-that-think` as a possible typing-time reference. The [supplied GitHub URL](https://github.com/onepixelaway/interfaces-that-think) did not resolve in this check, exact-name web search found no repo, and the owner's [visible public repository list](https://github.com/onepixelaway) did not include it. Its availability, license, code, and claimed behavior remain **unverified**. Do not count it as reusable code until the correct public source is found.

## Recommended validation before choosing a stack

1. **Capture pilot:** run Noty and Noted, inspect their relevant source modules, and test a global shortcut over a browser and another app; check focus return, blur/darken window behavior, two simultaneously open editable dialogs, selected-text wikilink creation, persistence of unfinished writing, and source reference capture. Neither repo claims that exact combination. [Noty](https://github.com/aimen08/noty), [Noted](https://github.com/fabriziosalmi/noted).
2. **Organization comparison on maker examples:** make a small consented corpus of real captures and human-reviewed candidate destinations/links. Compare rules + FTS5, embeddings, Laya, and Jev (if API access exists) on wrong confident routes, abstention, latency, local resource use, and ongoing cost. Use a held-out set. Generic memory QA or tag accuracy cannot establish that a note returns at the right moment. [Laya evaluation harness](https://github.com/NandhaKishorM/laya), [SQLite FTS5](https://www.sqlite.org/fts5.html).
3. **Retrieval pilot:** choose one actual target app and a single point of decision with the maker. Prototype an in-page cue and the destination click. Test route changes, editor focus, draft content access, and whether the offered note leads to an act, using [Web Remainder](https://github.com/farukak/web-remainder) and [Chrome's content-script constraints](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) as the starting references.

No code was copied, run, or benchmarked for this note. Repository activity counts are inspection signals as of 2026-09-29, not maintenance guarantees. License descriptions identify the upstream license; a later product must review copied files, transitive assets/models, and redistribution obligations at the actual commit selected.
